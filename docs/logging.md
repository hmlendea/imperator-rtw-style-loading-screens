# Logging

## Overview

This mod has no logging infrastructure. It contains no executable code, no runtime, and no processes that generate log output.

## Logging Framework

None. No logging library (Serilog, NLog, log4net, Winston, etc.) is used or required.

## Log Levels

Not applicable. No log entries are produced by the mod.

## Structured Fields

Not applicable. No structured logging.

## Correlation

Not applicable. No request tracing, correlation IDs, trace IDs, or span IDs.

## Sinks / Destinations

None. No console, file, database, or external service logging.

## Redaction / Masking

Not applicable. No sensitive data processed or logged.

## Retention

Not applicable. No logs to retain.

## Sampling

Not applicable. No log sampling.

## Performance Considerations

Zero overhead. No logging code executes.

## Error Logging

Not applicable. No exceptions to log. Asset loading errors are handled by the host game (Imperator: Rome) and appear in the game's log, not a mod-specific log.

## Audit Logging

Not applicable. No security-relevant events generated by the mod.

## Configuration

None. No logging configuration files, environment variables, or runtime level changes.

## Game Log Integration

While the mod itself produces no logs, the host game (Imperator: Rome) logs mod-related events in its own log file:

**Game Log Location**: `<game>/logs/game.log` (platform-dependent)

**Relevant Game Log Entries**:

```
# Mod loading
[Mod] Loading mod: rtw-style-loading-screens
[Mod] Mounting path: mod/rtw-style-loading-screens
[VFS] Mounted: mod/rtw-style-loading-screens/gfx/

# Asset loading (success)
[Texture] Loaded: gfx/loadingscreens/load_3.dds

# Asset loading (failure - silent fallback)
[Texture] Requested: gfx/loadingscreens/load_5.dds
[Texture] Fallback: vanilla/gfx/loadingscreens/load_5.dds

# Asset loading (failure - corrupt)
[Texture] Failed to load: gfx/loadingscreens/load_7.dds
[Texture] Error: Invalid DDS header
```

These entries are generated by the game engine, not the mod. They are useful for troubleshooting (see [Troubleshooting](./troubleshooting.md)).

## Future Considerations

If the mod ever gains executable components (unlikely per design), logging would need:
- Structured logging framework (Serilog recommended for .NET / Winston for Node.js)
- Correlation ID propagation
- Redaction of sensitive data
- Configurable levels and sinks
- Audit trail for security events

Current architecture: none of the above required.
